# Plan: plan-local-whisper-meeting-transcription

**PRD:** @docs/prd-local-whisper-meeting-transcription.md
**Дата:** 2026-09-07

**Подход к тестам:** в каждой фазе тесты пишутся до реализации (красные), реализация ведётся до
их позеленения. Unit-тесты `WhisperSttService` мокают `child_process` (реальный whisper.cpp/ffmpeg
в CI и pre-commit не нужны). e2e (`pnpm --filter api test:e2e`, vitest, нужен Postgres) остаются на
детерминированной заглушке через `.overrideProvider(STT_SERVICE)`. Реальный транскрипт проверяется
вручную на заранее известном коротком аудиосэмпле (вывод Whisper недетерминирован). UI веб-фазы
проверяется через Playwright MCP (браузерного тест-раннера в проекте нет — вне скоупа PRD).

## Фазы реализации

### Фаза 1: Бэкенд — реальная транскрибация WAV через whisper.cpp (Tracer Bullet)

**Цель:** при `STT_ENGINE=whisper` загруженная WAV-запись проходит `pending → processing → done`,
и в `transcriptText` попадает реальный текст от whisper.cpp с моделью `tiny` (happy path).
**Затрагивает:** backend

**Задачи:**

- [ ] Тесты до реализации (красные): unit `WhisperSttService` с замоканным `child_process` —
      сборка аргументов запуска (`WHISPER_BIN_PATH`, `-m` → `WHISPER_MODEL_PATH`, входной путь,
      язык из `WHISPER_LANGUAGE` либо авто, формат вывода plain-text) и парсинг вывода в текст;
      unit на `FileStorageService.absolutePath(storageKey)` — валидный ключ → путь внутри
      `baseDir`, `..` / абсолютный путь / разделители → отказ (барьер `resolvePath`).
- [ ] Расширить `SttInput` полем `storageKey`; прокинуть его из `MeetingFileProcessingQueue`
      (уже читает строку `MeetingFile`); обновить `StubSttService` и e2e-фейк STT под новый
      интерфейс.
- [ ] Добавить `FileStorageService.absolutePath(storageKey)` (переиспользует `resolvePath`).
- [ ] Реализовать `WhisperSttService implements SttService`: `child_process` → whisper.cpp с
      моделью `tiny`, язык из `WHISPER_LANGUAGE` (пусто → авто-детект), захват вывода в UTF-8,
      чтение результата в plain-text; временный файл вывода удаляется в `finally`.
- [ ] Фабрика провайдера `STT_SERVICE` в `MeetingFileModule` по `STT_ENGINE` (`whisper` | `stub`,
      на этой фазе дефолт `stub` — безопасно для локалки без движка); `STT_ENGINE`,
      `WHISPER_BIN_PATH`, `WHISPER_MODEL_PATH`, `WHISPER_LANGUAGE` + документированная команда
      загрузки модели `tiny` и запись в `.gitignore` — в `apps/api/.env.example`.

**Когда готова:** `pnpm --filter api test` зелёный (unit на замоканном `child_process`);
`pnpm --filter api test:e2e` зелёный на stub-override, заглушечный транскрипт не изменился;
вручную при `STT_ENGINE=whisper` загрузка короткого WAV с известной речью даёт
`pending → processing → done` и `transcriptText` с реально произнесёнными словами; Python в
рантайме API не используется.

### Фаза 2: Бэкенд — конвертация не-WAV через ffmpeg

**Цель:** любые разрешённые аудио/видео форматы (mp3/m4a/webm/ogg/mp4/mov) транскрибируются —
перед whisper входной файл конвертируется в 16 кГц моно 16-bit WAV; временные файлы всегда
убираются.
**Затрагивает:** backend

**Задачи:**

- [ ] Тесты до реализации (красные): unit — для не-WAV mime строится вызов `ffmpeg`
      (`-ar 16000 -ac 1`, 16-bit) во временный файл, и в whisper уходит путь этого WAV; для
      `audio/wav` конвертация пропускается; сконвертированный WAV удаляется и после успеха, и
      после ошибки (мок `child_process` и ФС).
- [ ] Добавить в `WhisperSttService` шаг конвертации через `child_process` → `ffmpeg` во
      временный файл (`os.tmpdir()` или `WHISPER_TMP_DIR`), с пропуском для уже подходящего WAV.
- [ ] Гарантированная очистка: сконвертированный WAV и файл вывода whisper удаляются в `finally`
      на обоих путях (успех/ошибка).
- [ ] `WHISPER_TMP_DIR` (если вводится) — в `apps/api/.env.example`; прогон
      `pnpm --filter api test` и `test:e2e` — зелёные.

**Когда готова:** тесты фазы зелёные; вручную загрузка mp3 и mp4 с речью → `done` с реальным
транскриптом; после `done` и после `failed` в каталоге загрузок и во временном каталоге не
остаётся WAV-файлов.

### Фаза 3: Бэкенд — устойчивость: ошибки, таймаут, остановка приложения

**Цель:** любой сбой движка переводит файл в `failed` без частичного транскрипта, существующий
`reprocess` перезапускает обработку; зависшая транскрибация обрывается по таймауту; идущий
подпроцесс убивается при остановке приложения; очередь остаётся одним воркером.
**Затрагивает:** backend

**Задачи:**

- [ ] Тесты до реализации (красные): unit `WhisperSttService` — каждая ветка → исключение: нет
      бинарника (ENOENT), нет модели, `ffmpeg` отсутствует / ненулевой код, whisper ненулевой
      код, превышен `WHISPER_TIMEOUT_MS`, пустой/пробельный вывод; тест, что при отмене
      подпроцесс получает `kill`.
- [ ] Интеграционные тесты очереди: `transcribe` бросает → статус файла `failed`,
      `transcriptText` не записан, затем `reprocess` (существующий) снова ставит в очередь; две
      записи, загруженные подряд, обрабатываются последовательно — вторая остаётся `pending`,
      пока первая не `done`/`failed` (`concurrency = 1`).
- [ ] Реализовать в `WhisperSttService` таймаут `WHISPER_TIMEOUT_MS` (env, дефолт в коде) с
      `kill` подпроцесса и внятной ошибкой; классифицировать все перечисленные сбои во вброшенную
      ошибку (без частичного результата).
- [ ] Проброс отмены: `MeetingFileProcessingQueue.onModuleDestroy` сигналит движку прервать
      текущий подпроцесс (`AbortSignal` / явный `kill`); убедиться, что e2e `afterEach` с
      `app.close()` не висит и не оставляет процессов-сирот `whisper`/`ffmpeg`.
- [ ] `WHISPER_TIMEOUT_MS` в `apps/api/.env.example`; прогон `pnpm --filter api test` и
      `test:e2e` — зелёные.

**Когда готова:** тесты фазы зелёные; смоделированные сбои (нет бинарника / нет модели /
`ffmpeg` / ненулевой код whisper / таймаут / пустой вывод) дают `failed` без `transcriptText` и
успешный `reprocess`; e2e с `app.close()` в `afterEach` не зависают; две записи подряд
транскрибируются последовательно.

### Фаза 4: Бэкенд — онбординг движка, env-валидация, документация

**Цель:** воспроизводимая установка whisper.cpp + модели `tiny`, проверка конфигурации на старте,
синхронная документация; дефолт `STT_ENGINE` переключён на `whisper`.
**Затрагивает:** backend (скрипты, конфиг, docs)

**Задачи:**

- [ ] Тесты до реализации (красные): unit на `validateEnv` — при `STT_ENGINE=whisper` и
      отсутствующем `WHISPER_BIN_PATH`/`WHISPER_MODEL_PATH`: `production` → бросает, вне
      production → warn; при `STT_ENGINE=stub` проверок движка нет.
- [ ] Скрипт загрузки модели `tiny` в `WHISPER_MODEL_PATH` (pnpm-скрипт в `apps/api`); записи
      для файла модели и бинарника в `.gitignore`.
- [ ] Расширить `validateEnv` проверкой наличия бинарника и модели при `STT_ENGINE=whisper`
      (фатально в production, warn вне); переключить дефолт `STT_ENGINE` на `whisper` в фабрике
      `MeetingFileModule`.
- [ ] Обновить `apps/api/CLAUDE.md` (выбор движка, зависимость от `ffmpeg`, стратегия тестов,
      стабильные env), `src/meeting-file/CLAUDE.md` при наличии, разделы переменных окружения в
      корневом `CLAUDE.md` и `README.md`; финализировать `apps/api/.env.example` (все `WHISPER_*`
      и `STT_ENGINE` с описанием авто / `ru`).
- [ ] Прогон `pnpm lint && pnpm typecheck && pnpm test && pnpm --filter api test:e2e`.

**Когда готова:** тесты фазы зелёные; pnpm-скрипт кладёт модель `tiny` в `WHISPER_MODEL_PATH`;
файл модели в git не попадает; при `STT_ENGINE=whisper` без бинарника/модели старт падает в
production и предупреждает вне его; `pnpm --filter api test:e2e` проходит без whisper/ffmpeg
(stub-override); `.env.example` и все `CLAUDE.md`/`README.md` согласованы.

### Фаза 5: Веб — проверка UI и сквозной прогон

**Цель:** реальный движок не ломает существующий UI страницы встречи — статус «Обрабатывается»
во время работы Whisper, реальный разворачиваемый транскрипт после `done`, обновление поллингом
без перезагрузки, путь ошибки с кнопкой «Повторить».
**Затрагивает:** frontend (проверка), сквозной прогон

**Задачи:**

- [ ] Проверка в браузере (Playwright MCP, сервер уже поднят): загрузка реальной записи →
      карточка файла показывает «Обрабатывается», затем «Готово» без перезагрузки (существующий
      поллинг); транскрипт разворачивается/сворачивается и содержит реальный текст.
- [ ] Проверка пути ошибки в браузере: недоступная модель / битый звук → статус «Ошибка» +
      кнопка «Повторить»; повтор перезапускает обработку и доводит до «Готово».
- [ ] Только если реальные тайминги ломают UX (долгий `processing`) — минимальная правка
      текста/индикатора в `apps/web/src/components/meeting-files.tsx` в рамках PRD (без новых
      статусов и без изменения контракта).
- [ ] Финальный прогон `pnpm lint && pnpm typecheck && pnpm test && pnpm --filter api test:e2e`.

**Когда готова:** в браузере загруженная запись проходит «Обрабатывается» → «Готово» с реальным
транскриптом без перезагрузки страницы; путь ошибки показывает «Ошибка» и рабочую кнопку
«Повторить»; все проверки (`lint`, `typecheck`, `test`, `test:e2e`) зелёные.
